# Контрольная работа №5

## Общее описание

В рамках трёх практических занятий были изучены и реализованы ключевые технологии современной веб-разработки:

1. **Сборка фронтенд-приложений** с помощью Webpack и Vite.
2. **Создание GraphQL API** на базе Apollo Server.
3. **Асинхронное взаимодействие сервисов** через брокер сообщений RabbitMQ.

Каждая работа включает готовый программный код, настройку окружения, тестирование и отчёт с результатами.

## Практическое занятие №25: Инструменты сборки

### Что было сделано

- Создано React-приложение с маршрутизацией (два маршрута: главная страница и страница «О нас»).
- Настроена сборка с использованием **Vite**.
- Реализован **lazy loading** для компонента на одном из маршрутов с помощью `React.lazy` и `Suspense`.
- Добавлен анализатор бандла **rollup-plugin-visualizer** (аналог webpack-bundle-analyzer).
- Выполнена production-сборка (`npm run build`) без ошибок.

### Основные техники оптимизации

- **Code splitting** – автоматическое разделение кода на чанки.
- **Tree-shaking** – удаление неиспользуемого JavaScript-кода.
- **Lazy loading** – отложенная загрузка компонентов.
- **Анализ бандла** – визуализация размера зависимостей.

### Результат

- Production-бандл оптимизирован, размер сокращён.
- Сгенерирован отчёт анализатора бандла (скриншот приложен к отчёту).


## Практическое занятие №26: GraphQL и Apollo Server

### Что было сделано

- Разработан GraphQL API для управления каталогом книг.
- Определена схема (SDL) с типами `Book`, `Author` и связью «один-ко-многим».
- Реализованы типы операций:
  - `Query`: получение всех книг, книги по `id`, всех авторов.
  - `Mutation`: создание книги и создание автора.
- Написаны резолверы для всех полей, включая вложенные (`author` у книги, `books` у автора).
- Запущен Apollo Server на Node.js.
- Протестированы минимум 3 запроса через Apollo Sandbox (скриншоты приложены).

### Технологии

- `@apollo/server`
- `graphql`
- Node.js (ES modules)

### Примеры запросов

```graphql
# Получить все книги с авторами
query {
  books {
    title
    author { name }
  }
}

# Создать нового автора
mutation {
  createAuthor(name: "Лев Толстой") {
    id
    name
  }
}
```

## Практическое занятие №27: Брокеры сообщений (RabbitMQ)

### Что было сделано

- Запущен RabbitMQ через Docker (контейнер с management-плагином).
- Реализован **Producer** в виде Express API (`POST /tasks`), который принимает задачу и публикует её в очередь.
- Реализован **Consumer (воркер)**, который читает задачи из очереди и имитирует обработку (с задержкой).
- Добавлена **Retry Logic** с экспоненциальной задержкой (минимум 3 попытки).
- Настроена **Dead Letter Queue (DLQ)** для сообщений, не прошедших обработку.
- Запущены минимум 2 воркера одновременно для демонстрации распределения задач.

### Технологии

- `amqplib` (Node.js)
- Express
- RabbitMQ (Docker)
- Docker Compose

### Результат

- Система асинхронной обработки задач с отказоустойчивостью.
- Задачи равномерно распределяются между воркерами.
- При ошибках происходит повтор с увеличивающейся задержкой.
- Необрабатываемые сообщения попадают в DLQ и не теряются.
